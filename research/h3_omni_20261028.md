# FastH3 Omni、Ref2VA max 與 hybrid 查核

查核日期：2026-10-28。目的：整合現有 ComfyUI script，並區分模型、參考圖編碼與 hybrid 的效果。此處沒有 GPU 生成或身份相似度對照結果。

## Omni 的實際模型與用法

目標是 FastVideo／Nuva Lab 的 [FastH3 Omni ComfyUI release](https://huggingface.co/FastVideo/FastH3-Omni-Comfy)，以 MiniMax H3 Ref2VA 為基礎的八步蒸餾模型。它與舊 FastH3 V2 的 T2VA／FL2VA checkpoint 不同。原生入口是 `MiniMaxH3ReferenceToVideo`，文字依輸入順序引用 `<Picture N>`、`<Video N>`、`<Audio N>`。發布者要求 8 步、guidance 1、video/audio shift 12/3，以及含視覺塔的 Qwen3-VL encoder、video VAE 與 audio VAE；八步已在模型內，不另加 Turbo adapter。

原生 starter 採 Euler/simple、BasicGuider（guidance 1）、8 steps、shift 12/3、dense attention、一張 reference。Euler/simple 是這份 starter 的選擇，發布者卡片沒有指定唯一 sampler。沒有額外 VSA gate transplant 或 Turbo LoRA。多圖／影片／音訊可用原生節點的自訂 API graph；此 starter 不宣稱涵蓋所有 Omni 輸入形式。

[轉檔契約](https://huggingface.co/FastVideo/FastH3-Omni-Comfy/blob/82eff2a6eee6c962846879f4bab52610a4df24d3/conversion/CONVERSION.md) 指出原 FastVideo 有 32-interval PDD heads，八次 forwards 對應 `[0,4,8,12,16,20,24,28,32]`。原生 ComfyUI 的 PDD unit grid 與 sparse-attention 幾何不完全等同，不能照抄 V2 的 video shift 10 或外部 runtime 的成績。發布者的 packaging 驗證以 CPU 結構為主，並未提供此包的 GPU 端到端驗證。

## 網友的 match → max 做法

[ComfyUI 官方指南](https://docs.comfy.org/tutorials/video/minimax/minimax-h3#setting-the-output-resolution) 與 [固定版原生節點](https://github.com/Comfy-Org/ComfyUI/blob/8f04fd6ecf4a548937971e840af2a985529fab76/comfy_extras/nodes_minimax_h3.py) 支持這項做法的機制：`match` 按生成畫面的像素面積縮小 reference；`max` 保留至最高 2048px 短邊，兩者都不放大小圖，並對齊 32 倍數。`max` 不是提高輸出解析度。

節點說明將 `max` 用於較佳 identity fidelity，同時警告 reference tokens 會經過每一步，可能慢數倍。[InvokeAI 的實作文件](https://invoke-ai.github.io/InvokeAI-7/users-guide/video-generation/minimax-h3/) 也把 Max 設為較高細節、Match 設為較快。這支持「大張原照可保留更多身份細節」的判斷，沒有證明每張圖或每個 prompt 都會更像本人。小圖無法藉此增加原本不存在的細節，且記憶體成本會上升。

Notebook 已加入 `REF_IMAGE_SIZE`，預設 `max`；兩個 native Ref starter 均可切換。Omni 的 Python 預設也為 `max`，既有 Ref2VA-VSA Python 預設保留 `match`。比較時應固定相同原照、prompt、seed、步數及輸出尺寸，只改這個值；本次未執行該 GPU A/B。

## FL2VA + Ref2VA hybrid 是另一件事

[smhfacct 的 hybrid 模型卡](https://huggingface.co/smhfacct/Minimax-H3-fl2va-ref2va-hybrid-models) 描述 tensor-selection merge：以 FL2VA 作母模，換入後段 blocks 的 Ref2VA `adaln_proj`，沒有再訓練。作者推薦先試 b25–49；換入更多 Ref2VA blocks 時，reference 能力與原始畫質有取捨，作者明確稱其為主觀、非完整驗證的實驗。[InvokeAI](https://invoke-ai.github.io/InvokeAI-7/users-guide/video-generation/minimax-h3/) 提供相似的 runtime 權重替換功能，預設邊界也是 block 25。

因此，hybrid 不是同時執行兩個模型，也不是 `ref_image_size=max`。目前讀到的來源沒有控制變因的人物身份比較，無法支持「普遍比純 Ref2VA 更像本人」。它主要試圖改善 reference 生成的畫質；本次僅記錄研究，不把這些社群 merge 自動套到已蒸餾的 Omni。
