# 影片驗收與放行

## 判準與授權

在現有 plan／ledger 記明必需內容、不可接受缺陷、可接受差異及交付用途，沿用使用者已定的基準與取捨。節奏、情緒、人物一致性等主觀要求，優先用已認可作品或正反例說明；缺少基準且會改變成品方向時才請使用者決定，不自創精確分數或逐支簽核門檻。

記明本次可自行修正、放行的範圍與既有成本／時間／嘗試限制。品質放行與外部發佈分開；發佈和新增範圍外費用仍依原任務授權。

## 通用驗收

先把 verdict 對應到使用者要求或已定的判準／事件區間，分開技術格式、動作、外觀、取景、聲音和剪接。觀察到某時點的狀態不自動證明過程；未指定的時間、手別、道具細節不自行升格成失敗條件。

概覽用來定位，重要短暫事件用足夠密度或 native 連續影格。全畫面看構圖與物件關係，原像素局部查必要細節；moving ROI 要核對當時的實際位置。身份對照原始基準和可讀視角，大小／銳利度或未校準相似分數不替代外貌判斷。

每個判準記實際 reviewer、來源 hash、evidence ID／時間、理由與覆蓋：

- pass：證據支持所需內容，並說清已檢查的範圍。
- fail：有足以反證哪項既定要求的證據。
- unknown：未提供、未看清、遮擋或時序覆蓋不足；取下一份有辨別力的證據。

「沒抽到」不能直接改稱「沒發生」，末態正確不替代因果。重要要求未通過時保留其狀態，避免用平均分或其他項目改善掩蓋。使用者明確要單輪保存／已知缺陷版時可按要求交付，附真實狀態，不改稱品質通過。

需要評估節奏或流暢度時看實際速度播放；只看幀序則保留該覆蓋限制。ASR、字幕字串和 audio stream 解碼是不同證據；實際未收到／未聽聲音時不聲稱聽驗。ASR 的同音異字、專名誤寫或漏掉短促插話，需回查原音，不能僅憑轉錄判定發音錯誤或缺句。

後製字幕前檢查 raw 是否已有文字／語音，依實際位置處理並看字幕前中後和空白間隙。換音、裁切、身份修正、放大或插幀後評審相應新版本；生成的細節不回填原片證據。

選材與剪接審查依 [素材事實與入出點理由](../../video-production/references/adaptation-shot-and-edit.md#先記素材事實再決定剪哪裡) 對照實際區間；風格或重複性意見依該頁的 [創作選擇](../../video-production/references/adaptation-shot-and-edit.md#審查方法與創作選擇) 引用位置及影響，沿用使用者已接受的節奏與表演尺度。

## 情緒、發聲方式與嘴型

角色敘事按 [情緒與表演](../../video-production/references/emotion-and-performance.md) 的既定設計驗收。核角色目標、觸發、表情／行為反應、逐句語氣與情緒交接，確認觀眾能從實際聲畫讀到所需變化與反差。刻意平靜或死寂可符合設計；字句完整但所有場次套同一平讀語氣，不能代替表演要求。

逐句對照其語音時窗：口說有相應發音動作；心聲有較空洞的內在聽感、保留當下情緒且當事角色沒有該句發音嘴型；無聲說話有與心聲同步的嘴型，沒有另一次現場口說。畫外口說與旁白依各自來源和聲音位置判斷，在鏡人物的反應符合其可聽／可見資訊。

表情／動作、口型、語氣／空洞聽感與跨鏡情緒節奏分開記錄證據和 verdict。嘴型用語音期間的實際播放或足夠連續影格核對；語氣、聲音處理與情緒節奏需實際聽驗／觀看。ASR、音量或單張閉嘴圖不能把未檢查的項目轉成 pass；缺乏相應能力時保留該項 unknown，按下述放行規則處理。依具體缺陷修正受影響的表演、配音／混音或接點，不靠追加字幕或配樂把尚未成立的表演標成完成。

## 評審分工與放行

交付合格成片時，優先由主代理指派未參與該次製作的獨立 reviewer。單輪試片或已知缺陷交付按使用者指定範圍處理。

- 製作者整理實際成片、來源與證據，完成自檢及授權內修正；自檢記為自檢。
- Reviewer 取得要求、原始基準、待審版本、必要媒體／工具和本輪界線，先依證據形成判斷，再處理製作者的說明。回傳逐項 verdict、時間證據、覆蓋限制和缺陷；受派 agent 是葉代理，不另派工或擴大生成／API 授權。
- 主代理核對成片版本、關鍵證據與覆蓋，處理矛盾並記錄放行理由。可採信可追溯的獨立評審，不必重做每項檢查；衝突、核心 unknown 或後續修改則覆核受影響內容。

依判準確認 reviewer 的實際影像、播放與聽驗能力；同一份稀疏抽幀換一個 agent 看，仍只有該覆蓋。無獨立 reviewer 時可由主代理直接驗收並如實記錄分工；需要的媒體能力不足時，先在既有授權內補工具或交給具能力的審查者，未補足項目保留 unknown。

必需判準全數 pass 且證據覆蓋足夠，才可標為合格成品。使用者未要求逐支簽核時，在既定判準與授權範圍內完成放行及交付。現有評審／交付紀錄須指向實際成片路徑與 hash、所採用的評審和判準，記錄放行負責者、時間、決定、理由及未達項；試片／已知缺陷版保留真實 verdict。

實際檔案可取用、必要評審與可追溯的放行結論已完成時，先提供檔案連結、結果及覆蓋限制；較長報告或文件整理可後補。記錄已有評審結論即可完成這次交付，不讓書面整理重開已完成的驗收。若先提供仍在驗收的檔案，標明預覽／pending；核心 unknown／fail 仍依上面的放行規則處理。

## 修正與升級

Fail 先處理具體缺陷；unknown 先補有辨別力的證據；評審分歧先回到原判準與爭議區間，不能以多數票消除核心 unknown。修正及補證據沿用本輪成本、時間與嘗試界線；達界線便保存版本與真實狀態，按已授權的交付範圍收尾。

需要改必需內容、降低既定標準、超出授權／預算，或缺少會改變結果的決策基準時，才向使用者升級。附具體時間片段、未達要求、已做處理、選項與建議；一般缺陷修正及可自行補齊的證據由代理完成。

## 校準與抽查

重複製作同類影片時，可用使用者或其授權審查者已認可的可接受／不可接受樣本校準 reviewer，先獨立判斷再比對，特別記錄「放行但覆核不合格」的漏檢及原因。依結果在現有專案紀錄寫明可自主放行的判準類型、模型／後製路徑、素材條件、reviewer 能力，以及抽查者與頻率；不預設固定成功次數或抽查比例。

判斷穩定的範圍可減少使用者介入，由使用者或其指定的審查者隨機抽查已放行作品；核心判準改變、模型／後製／reviewer 能力改變或重大漏檢時，收窄受影響的自主放行範圍並增加覆核，更新判準或取證方式。校準不替代每支成片的實際驗收，也不要求使用者永久逐支親審。

## Studio 的證據工具

`studio.py inspect` 對已有 attempt 產生時間標記的全尺寸影格、事件密集取樣、接點、ROI和獨立音軌。預設概覽／event sampling 是工具設定，快速事件可用 native fps；欄位和命令見 [workflow.md](workflow.md)。FastH3 等獨立輸出用其自身檢查器或等價媒體工具，不假設已有 Studio attempt。

review-template 的每個 criterion 填來源證據。輸入／prompt／生成設定改變時建立對應的新 job，原 job／review 保留為舊版本紀錄。影片改動後，新評審須綁定新版 hash 與 evidence manifest；核對來源、時鐘與改動範圍後，重驗受影響判準及接點，未受影響判準的既有結論也須對應新版可解析的證據。

selection 指向實際版本，接點 review 核左右影片、狀態與音訊。匯出後查 stream duration、fps／frame count、聲道和完整解碼，再看實際接點、重要區間和片尾。

匯出工具將 `delivery.json.final_content_review` 建立為 pending；主代理在成片實際驗完後才更新結果並指向上述成片評審紀錄。這是依證據維護的交付紀錄，匯出成功不會自動完成內容放行。

## 可選 API 評審

本 repo 的 `review_opus.py` 以解碼圖片／文字建立 payload，沒有直接 MP4／音訊聽驗。需要此路徑時先看工具 help 和可用 model／key；dry-run 可檢 payload，只有真實返回的 request／model／usage 才算 API 執行。已有授權才呼叫，失敗不盲重試／換 provider。傳入的圖片覆蓋與provider縮圖限制仍要記錄，不把含原照／控制幀的評審當生成條件。
