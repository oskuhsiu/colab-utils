# Colab runtime 監看與恢復

## 資源與作業生命週期

適用付費 runtime 的準備、執行、恢復和停止；離線規劃／文件／既有素材審查不需要配置 GPU。

使用者要求用 Colab 製作或處理其提供的照片／影片時，任務包含將必要素材與設定上傳至其指定的 Colab session。逐段與批次執行沿用同一任務授權，不另設素材上傳同意關卡。

啟動前準備一批已授權、可獨立執行的 jobs、素材及保存方式，核對當次資源／時間／CU／嘗試限制，並接好能自動續跑的控制器與獨立停止入口。配置或沿用資源時比對實際 endpoint、硬體、可用 RAM／磁碟及費率；採用當次停止餘量，不把某次預算或硬體固定成通用預設。

原生 h3-omni 的冷啟動可使用 [預備包與部署到首鏡](../../../doc/COLAB_QUICK_DEPLOY.md)：先離線封好原 project adapter、第一鏡與全部輸入，再由單一 detached worker 接續環境、權重、server 和首鏡。帶既有預算 guard 的當次 admission；有原 shot 時先對帳，服務 READY 不能代替模型已載入或本機成果已保存。

只驗證安裝、傳輸和斷線恢復時，可使用同頁的 `colab_preflight_probe.py` 無生成分支；T4 的實測只適用這些流程，不外推 A100 載入／推論能力。離線環境包要把傳輸成本算進比較；不能只用 VM 內還原較快就推定省 CU。

付費長批次先依 [連線故障快速分流](connection-recovery.md#付費批次啟動前) 準備可恢復的身分、租約期限和替代控制入口；發生執行／上傳逾時、401／404、session 或路徑消失時，立即進入該流程。

## 批次排程：生成、保存與驗收並行

GPU 由單一排程擁有者依序執行；下載／保存及 CPU 驗證／內容審查各自有工作線。後端確認一段完成、產物已封存且可取回後，**立即提交下一個已就緒且預算准入通過的 job**。上一段仍在下載、hash、完整解碼或內容審查，不是下一個獨立 job 的前置條件；即使審查尚未完成，後面的獨立鏡頭仍可繼續。

```text
GPU:     G1 ----- G2 ----- G3 ----- R1 ----- G4
Save:           D1 ----- D2 ----- D3 ----- ...
Review:                Q1 -------- Q2 ----- ...
```

- 把待跑 jobs 保留在控制器的可排序隊列；後端同時最多一個執行中的工作。新 job 的選取與提交由常駐於本次批次的控制器接續，不等主代理讀完日誌或回完訊息。
- 已獲准的重跑使用新 attempt ID、保留舊產物，插在**所有尚未提交的一般 jobs 前面**；多個重跑按加入順序執行。已在 GPU 執行的工作正常完成，不為插隊中斷它。新 attempt 仍遵守原嘗試限制和預算，不自動把 QA fail 轉成無限重抽。
- 分開記錄執行、產物保存和審查狀態。`remote_complete` 可釋出 GPU 工作線；`local_saved`、完整性通過、`technically_valid`、內容 pass 各有自己的證據。續跑不代表前段已通過品質驗收。
- 只有真正使用上一段生成末幀、實際選材狀態或修正結果的 job 才等待該依賴。先跑其他 ready jobs；失敗只暫停受影響的分支。全 route 的技術故障、預算不足、保存積壓危及磁碟或截止時間，也會暫停新提交並記明原因。
- 保存工作持續取回已完成產物，不等整批末尾；下載失敗恢復原產物的傳輸，已完成推論不因此重新生成。一般 CPU 審查不佔 GPU 工作線；只有明確需要 GPU 的後製／檢查才另排 GPU job。
- 沒有可執行工作時，先完成必要取回與可恢復的完整性保存，再通知資源擁有者釋放本次 endpoint。本機完整解碼、ASR、長時間內容審查、報告及最終剪輯可在釋放後繼續。只有已知下一個工作及短暫等待／重載成本支持保留時才留 GPU，不為等待可能發生的重跑持續空轉。

原生 ComfyUI 的可分離執行與共用控制器見 [執行工具](workflow.md#原生-comfyui-批次接續)。各 adapter 保留自己的 job／receipt 身分；同一 kernel 的 setup、卸載與全域配置仍依序執行。

## 提交前的預算判斷

每次提交新付費工作前，用對應 endpoint、帶時間戳的最新觀測重新判斷剩餘預算與截止時間。可沿用有效 watcher 的最新資料；準備、診斷或審查等待使觀測過時時，提交前更新它。

使用本次 endpoint 的費率與累計配置區間估算本次成本；帳戶 usage／扣款含其他 VM 時，分開記錄，不把帳戶合計費率冒充本台實際費率。保守上界須有來源和適用條件。

准入看「已承諾工作加上候選 job」到必要產物安全保存的**流水線完成時間**，包含載入、推論、GPU 解碼、編碼與保存工作尾端。重疊的生成與取回不能直接相加；已花費的冷啟不重複估入下一鏡，完整內容 QA 也不預設需要繼續租 GPU。只量 sampler 或遠端檔案存在仍不足以證明能保存，但這不等於必須先把每個前鏡都存完才續跑。

例如一條 GPU 線、一條取回線的保守估計可用：`取回完成_i = max(生成完成_i, 取回完成_(i-1)) + 取回時間_i`。多工作線按實際並行與積壓計算；必要完整性核驗計入保存尾端，內容評審另行排程。最後只保留**一次**本次停止／釋放餘量；若提前停止門檻已扣掉同一份餘量，不能再重複扣除。拒絕新 job 時記錄本次估計已用額度、完成時間、保存尾端、單一停止餘量與拒絕原因，區分使用者硬上限和自訂保守門檻。

剩餘額度不足以保存新結果時，先用已保存、符合必需內容的素材收尾，或記錄仍缺的必需內容。可選鏡頭與品質重抽也沿用這次提交判斷；已釋放的資源按停止狀態處理。

## 監看與保存

需要維持監看時，從下載／載入前開始，保存具時戳的 phase、作業身分、資源與日誌變化。頻率按工作成本、風險及讀取開銷選擇；先抓小型狀態，避免反覆取整包大日誌。程序或檔案曾存在不等於當前心跳，單次零利用率不等於卡住。

每個完成且可恢復的階段／片段及時抓回本機，核身分與 hash 後標為已保存，完整解碼通過再標技術有效；內容 verdict 由審查另寫。這些保存與核驗由獨立工作線進行，不能成為所有後續獨立鏡頭的全域等待條件。保存進度與失敗版本，不等整批末尾才封存。單一 CLI exit code、進度百分比或 ZIP 存在都不足以證明完成。

## 恢復與重試

連線故障按 [快速分流](connection-recovery.md#首個故障後的分流) 核對原 endpoint、更新租約、切換可靠通道及判定何時釋放。此流程的短時限限制的是控制通道排查，不是仍有進度的模型下載／載入／生成時間。

技術恢復和品質重抽分開。結果不確定的已提交工作保持 needs_reconcile，避免盲目重送；新 attempt／重試數依既有授權和限制。backend 的具體 marker／proxy 由其執行工具處理。

此 repo 的 Studio 以 `status/fetch` 核原 attempt，尚無完整資源 watcher 服務；H3／FastH3 使用其獨立工具。需要外部 watcher 時明確建立，讀取現有作業而不提交推論。下載通道或 QA 的故障先在各自工作線恢復；提交結果不確定或無法安全保存的風險才影響新的 GPU 准入。

## 保留與釋放

只在已知下一個工作、且預計等待／重載成本符合當次範圍時保留 GPU。需研究新工具、改程式或長時間 QA 時，把工作移到釋放後；重用模型須核對 namespace／handle 與載入設定，不能由先前 receipt 推定仍已載入。

使用者停止製作或達當次界線時，停止確定目標的作業／下載／內容後製，保存 partial，再釋放所屬資源並以伺服器 assignment／usage 驗證；404或本機清 cache 本身不是釋放證據。文件工作不恢復製作，已授權的既有素材唯讀審查仍可做。

記錄當次起末資源與帳戶觀測、計費範圍和未確認狀態；不從零利用率、SIGKILL或檔案缺失單獨推定原因，也不把過期快照當即時帳戶狀態。

同一 allocation 的 elapsed／費率估算截止於首次由伺服器確認該 endpoint 已釋放的時間；後續 status／stop 核對、本機 QA 和文件工作只補觀測，不延長已結束的估算區間。重新配置另開區間並累計到本次總額；帳戶實際扣費觀測與估算分列，保留各自口徑。
